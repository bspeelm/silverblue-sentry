# Design: milestones 3–7

Companion to `spec.md` + `spec-addendum.md`. Decisions here are binding for the code; deviations from
the spec are also recorded in the addendum (A9+).

## Shared shape

- **One execution path for jobs.** Every job is `sentry job <name>`. The TUI never re-implements a
  job: after its own preview + confirm modal it streams `sentry job <name> --yes` (via
  `Cmd::local(current_exe)`) into the run pane. Headless and TUI therefore write the same reports,
  the same `jobs.json` last-run records, and print the same output.
- **Plans before actions.** A job's `plan(ctx)` is read-only and returns `Plan { items }`. Each item
  carries a label, an optional byte estimate, preview lines and the `Cmd` that would run. `--dry-run`
  prints the plan; the TUI renders it in modals and on the Cleanup screen.
- **State files only for status.** `sentry status`, the dashboard Status panel and the tab badges read
  `reports/`, `jobs.json`, workflow `state.json` and `metrics/recorder.pid`; they never run collectors.

## M3 Audit (`src/audit/`)

| file | role |
|---|---|
| `snapshot.rs` | `Report { version, taken_at, tag, host, sections, errors, findings }`. Sections mirror collectors but store only stable, diffable facts: ostree (booted version, layered, local, removals, kargs, sig), flatpak apps (id, origin, flags, filesystems) + remotes + GL.nvidia, containers, listeners (keys + status), units (enabled user/system, failed, autostart), repos, shell hits, journal **counts only** (messages can hold secrets), `~/.cache` size + top dirs. A missing tool → section `None` + entry in `errors`. |
| `findings.rs` | Pure `derive(&Report, prev: Option<&Report>, &Baseline, &Config) -> Vec<Finding>`. `Finding { id, severity, category, message, evidence }`; `id` is stable across runs (`listener:0.0.0.0:22/sshd`, `flatpak-fs:com.valvesoftware.Steam:home`, `repo:_copr:…`). |
| `diff.rs` | Structural diff of two reports → `Vec<DiffLine { kind: Section/Add/Remove/Change/Same, text }>`; kargs use `similar` word diff. Rendered to the `.md` file and to the Diff pane. |
| `store.rs` | `reports/YYYY-MM-DD[-tag][-N].json` + `.md`; list (sorted by `taken_at`), load, find-by-tag, retention prune. |

Severity rules (spec §7, plus host-specific additions marked ✚):

| severity | rule |
|---|---|
| high | listener `NEW` (non-loopback, not baselined) · Flatpak app **gained** `host`/`host-os`/`home` since the previous report (or on the first report) · enabled COPR not seen in the previous report · suspicious rc pattern · deployment with invalid signature |
| medium | app from unverified origin · stale container with `$HOME` mounted · failed units · Flatpak FS flag that persisted from the previous report · COPR that persisted · ✚ enabled third-party (non-fedora, non-COPR) repo such as `updates-master.repo` |
| low | ✚ unused Flatpak runtimes (`flatpak uninstall --unused` preview) · ~/.cache over `cache_warn_mb` · ✚ stale `GL.nvidia-*` extension not matching the driver · ✚ failed logins in 24 h |

Baseline: `b` writes the finding id to `baseline.toml findings` (listener findings go to `listeners`
so the Network screen agrees). Baselined findings stay in the report with `expected = true`, render dim,
and are excluded from counts and badges. The baseline is re-applied at display time, so `b` takes effect
immediately without re-auditing.

Audit screen: findings table (severity · category · message) over an evidence box, diff pane on the
right (previous → selected report). `Enter` runs the audit (read-only, no confirm), `b` baseline,
`[`/`]` browse reports, `C-h`/`C-l` focus, `C-j`/`C-k` scroll the diff. Badge `!N` = open high findings.

## M4 Jobs (`src/jobs/`)

`JobId` enum: `audit`, `update-check`, `update-apply`, `cleanup-flatpak`, `cleanup-podman`,
`cleanup-ostree`, `cleanup-cache`. Cadence = config `[jobs]` → overridden by
`~/.config/sentry/cadence.toml` (machine-written by `e`; same rationale as `baseline.toml`). Last run is
recorded in `~/.local/share/sentry/jobs.json` (`{name: {at, ok, summary}}`) by the job process itself.

| job | plan (read-only) | action |
|---|---|---|
| audit | sections to collect | in-process snapshot + diff + findings |
| update-check | — | `rpm-ostree upgrade --preview`, `flatpak remote-ls --updates` → caches (same as `c`) |
| update-apply | `cached-update` summary + flatpak updates | `rpm-ostree upgrade` + `flatpak update -y`. **Refuses** when the kernel changes: that path is the `quick-update` workflow |
| cleanup-flatpak | `flatpak uninstall --unused` answered `n` (lists refs) · stale `GL.nvidia-*` extensions with du sizes | `flatpak uninstall --unused -y` · `flatpak uninstall -y <stale GL refs>` |
| cleanup-podman | stopped **plain podman** containers older than `stale_container_days` · dangling images (sizes from podman) | `podman rm <names>` · `podman image prune -f`. Toolbox/distrobox containers are never pruned automatically (they hold user state); they're listed as "remove from Containers if unwanted" |
| cleanup-ostree | du of `/var/cache/rpm-ostree` | `rpm-ostree cleanup -m` (`-b` opt-in item; `-r` never — only in release-rebase) |
| cleanup-cache | `~/.cache` children over 100 MB, sorted | `rm -rf` of opted-in `[cleanup.cache].delete_dirs` only (names validated: no `/`, no `..`) |

Cleanup screen = plan items from the four cleanup jobs with checkboxes (`Space`), selected total,
preview pane for the cursor item; `Enter` → confirm modal → run pane streams the selected items' commands
sequentially (`RunSpec` gains a command queue) and records each owning job once all its selected items
succeed. Jobs screen = table per mockup; `Enter` → plan fetched in the background → confirm modal →
stream `sentry job <name> --yes`; `e` → input line for the cadence (`30d`, `off`).

## M5 Workflows (`src/workflows/`, `src/checks/`)

- **Files**: seeded TOMLs are written to `~/.config/sentry/workflows/` the first time the Upgrade
  screen or `sentry workflow` runs, never overwriting user edits.
- **Format**: spec §9.2 plus `manual` (card text), `draft`, `dry_run`. `serde(deny_unknown_fields)` gives
  lint its unknown-field errors. Lint also checks ids (missing/duplicate), templates (undefined vars),
  `when` names, `sentry check <name>` names inside `run`, gate/kind/on_fail values.
- **Templating**: hand-rolled `{{ expr }}`: identifiers, integer and string literals, `+`/`-` on
  integers. Built-ins `current_version`, `booted_kernel`, `pending_kernel`, `old_kmod`, `home`.
- **Lazy freeze**: a built-in or `when` condition is evaluated the first time a step needs it and frozen
  into `state.json`. This is what makes `kernel_changed` correct: it's read after the `preview` step
  refreshed `cached-update`, and stays true after the reboots that make the live check false.
- **Runner** (`runner.rs`) is a pure state machine: `next(&RunState, &Workflow) -> Next::{Run(step),
  Gate(step), Reboot(step), Manual(step, text), Done}` plus `record(step, outcome)`. TUI and headless
  drivers share it.
- **Execution**: `run` steps execute `bash -c 'set -o pipefail; sentry(){ <abs exe> "$@"; }; <cmd>'` on
  the host, output appended to `steps/<id>.log`. Steps containing `sudo` run with the TUI suspended
  (password prompt on the terminal) and are tee'd to the log. `timeout` kills the step.
- **rpm-ostree dry-run sibling**: `install`/`uninstall`/`override` get `--dry-run`, `upgrade` gets
  `--preview`; `rebase` has no dry-run (verified on rpm-ostree here), so its card says so.
- **Reboot**: card → confirm modal → state saved with boot id → `systemctl reboot`. On start, a saved
  boot id ≠ `/proc/sys/kernel/random/boot_id` marks the reboot done; equal means it never happened → the
  card asks again.
- **Abandon**: `a` → modal: leave as-is, or run the `rollback = true` steps.
- **Auto steps** run without confirmation, but after a resume only once the Upgrade screen has been
  opened (the banner says "press 0 to continue"), so nothing runs behind the user's back at startup.
- **Checks** (`sentry check …`, exit 0/1 + one line): preflight, booted-version, booted-kernel,
  kernel-changed, nvidia-module, nvidia-loaded, rpmfusion-version, rpmfusion-pinned, kargs,
  secureboot-mok, kmod-local, akmods-built, flatpak-gl-nvidia, flatpak-idle, master-repo-present.

## M6 Recorder (`src/recorder/`)

- `metrics/ring.bin`: 64-byte header (`SNTYREC1`, version, record size, capacity, write index,
  interval) + fixed 128-byte records (ts, cpu %, mem used, swap used, rx/tx B/s, load1, cpu °C,
  GPU util/°C, `/` used %, top-3 processes by CPU). Capacity = min(retention, max_mb).
- `metrics/recorder.pid` (pid, interval, started) marks a live recorder; stale pids are ignored.
- Sampling: sysinfo CPU+mem only, `/proc/net/dev`, statvfs; nvidia-smi at most once a minute; `ss` for
  `new_listener` once a minute. Alerts debounce (fire once until the condition clears) via `notify-send`.
- History screen: per-metric graphs stretched over 6h/24h/72h (`[`/`]`), `←`/`→` scrub by ¼ window,
  avg/max stats, axis labels, alerts and recorder status. The dashboard pre-fills its graphs from the
  recording on start.
